Where a vendor page could not be fetched directly (OpenAI help center and openai.com return 403 to automated fetches), this is stated and the claim is marked lower-confidence.

## A. Claude subscription (Pro / Max)

### A1. May the subscriber's own app call `claude -p` / the Agent SDK on their claude.ai login?

#### What the governing documents say

**1. Consumer Terms (effective Oct 8, 2025) govern Pro/Max, including Claude Code.**
- Claude Code legal page: "Consumer Terms of Service - for Free, Pro, and Max users" — https://code.claude.com/docs/en/legal-and-compliance
- Consumer Terms §3 prohibits: "Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it, to access the Services through automated or non-human means, whether through a bot, script, or otherwise." — https://www.anthropic.com/legal/consumer-terms
- §2: "You may not share your Account login information, Anthropic API key, or Account credentials with anyone else. You also may not make your Account available to anyone else."
- Note: "these Terms" say the Commercial Terms govern API keys; "this does not include Claude.ai or Claude Pro use for individuals".

So automated access on a subscription is prohibited **unless Anthropic "explicitly permit[s] it"**. The question is whether the Claude Code docs count as that explicit permission for `claude -p` / SDK use.

**2. Anthropic's own docs document subscription-authenticated headless use.**
- Authentication docs, `claude setup-token`: "For CI pipelines, scripts, or other environments where interactive browser login isn't available, generate a one-year OAuth token with `claude setup-token`" … "This token authenticates with your Claude subscription and requires a Pro, Max, Team, or Enterprise plan. It can only make model requests, so it can't establish Remote Control sessions or fetch claude.ai connectors. MCP servers you configure locally still work." — https://code.claude.com/docs/en/authentication
- Precedence list item 5: "`CLAUDE_CODE_OAUTH_TOKEN` environment variable. A long-lived OAuth token generated by `claude setup-token`. Use this for CI pipelines and scripts where browser login isn't available."
- Headless docs: "`--bare` is the recommended mode for scripted and SDK calls" but "bare mode doesn't use your subscription login" / "In bare mode, Claude Code never reads OAuth credentials or the system keychain." (Non-bare `claude -p` does use the subscription login.) — https://code.claude.com/docs/en/headless
- Help center, "Use the Claude Agent SDK with your Claude plan" (verbatim, fetched raw):
  - "Update October 7, 2026: Claude Max and Team plans now include monthly API credits. They cover the Claude API, Claude Managed Agents, and the Claude Agent SDK and claude -p when you run them with an API key from your linked Claude Console organization. Nothing changes for your plan: when you're signed in with your Claude plan, the Claude Agent SDK and claude -p still draw from your subscription limits."
  - "Update June 15, 2026: We've paused the previously-announced changes to Claude Agent SDK usage. For now, nothing has changed: Claude Agent SDK, claude -p, and third-party app usage still draw from your subscription limits."
  - https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan
- Legal page: "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK."

**3. The restrictions are aimed at developers offering claude.ai login to *others*.**
- Legal page, "Authentication and credential use":
  - "**OAuth authentication** is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications."
  - "**Developers** building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider. Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow."
  - "… Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code …"
  - "Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice."
- Agent SDK overview: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Use the API key authentication methods described in the Quickstart instead." — https://code.claude.com/docs/en/agent-sdk/overview
- Agent SDK overview also: "Use of the Claude Agent SDK is governed by Anthropic's Commercial Terms of Service, including when you use it to power products and services…" (this sits awkwardly next to the subscription-login path, which is governed by Consumer Terms — flag as ambiguity).
- Help center "Log in to your Claude account":
  - "Subscription plans can only be used by subscribers, and the usage included in these plans is designed to support ordinary use of native Anthropic applications, including the Claude web, desktop, and mobile applications and Claude Code."
  - "The preferred way to access Anthropic services using third-party software, tools, or services ("third-party tools"), including open-source projects, is through API key authentication … Anthropic may at its discretion allow paid subscribers who have enabled usage credits to use certain third-party tools … but reserves the right to draw use of such third-party tools from usage credits rather than subscription limits. … Use of third-party tools that misrepresent their identity to Anthropic's servers, attempt to route third-party traffic against subscription limits, or otherwise violate applicable terms or policies is prohibited and such use may be enforced against."
  - "If you're building a product, application, or tool for others, use API key authentication…"
  - https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account
- History (secondary sources, for context only): Feb 2026 a version of the legal page reportedly said using subscription OAuth tokens "in any other product, tool, or service — including the Agent SDK — is not permitted"; an Anthropic DevRel post called it a "doc cleanup". That wording is **not** on the current page. On April 4, 2026, Anthropic moved third-party harnesses (starting with OpenClaw) off subscription limits onto paid extra usage (InfoWorld, The Register, etc.). In May 2026 Anthropic announced moving Agent SDK/`claude -p` usage onto a separate credit from June 15; that change was paused (official notice above).

#### Personal single-user use
No Anthropic page directly addresses "a subscriber's own private, single-user app that spawns `claude -p` on each request". The documents speak of (i) "ordinary, individual usage of Claude Code and the Agent SDK", (ii) third-party developers offering login to *their users*, and (iii) "third-party tools".

#### Classification

| Scenario | Status | Basis |
|---|---|---|
| (a) Subscriber interactively driving Claude Code (terminal, IDE, desktop, Remote Control from phone), incl. custom MCP servers | **Clearly allowed** | Pro/Max help article; MCP docs; Remote Control docs |
| Subscriber running `claude -p` / Agent SDK themselves, on own login, for own scripts | **Allowed per current docs** (help center says it "draw[s] from your subscription limits"; `setup-token` documented "for CI pipelines and scripts") | help-center 15036540; authentication docs |
| (b) Subscriber's own backend process spawning `claude -p` (unmodified binary, own login/`setup-token`) on each request of a single-user app only they use | **Gray.** Not expressly addressed. Arguments for: docs explicitly support scripts/SDK on subscription; usage stays "individual"; no third-party users; unmodified binary signs in via Anthropic's own flow. Arguments against: Consumer Terms ban automated/non-human access unless "explicitly permit[ted]"; help center says subscriptions are for "ordinary use of native Anthropic applications"; Wise Wizard is a "third-party tool" in the help center's sense; limits assume "ordinary, individual usage"; Anthropic "may at its discretion" move such use to paid usage credits and enforce "without prior notice". | above |
| Same, but the app is internet-exposed and only the subscriber logs in | Same gray; risk increases if anyone else can use it ("You also may not make your Account available to anyone else") | Consumer Terms §2 |
| Offering "Sign in with Claude"/claude.ai login in your app; collecting/storing claude.ai tokens; serving other users on your plan | **Clearly disallowed** | legal page; Agent SDK overview; help center |
| Modifying/spoofing the client, extracting OAuth token to call the API directly from your own code (not via the Claude Code binary) | **Clearly disallowed** ("misrepresent their identity"; "collect, store, or intermediate … session tokens") | help center; legal page |
| Using `--bare` with subscription | Not possible technically (bare ignores OAuth) | headless docs |

Practical notes (factual): `setup-token` tokens last one year and "can only make model requests" (no claude.ai connectors, no Remote Control). Normal `/login` credentials expire and must be renewed; "A background session … or a Remote Control session that outlives the login stops making progress once the credential expires."

- "Both Pro and Max plans have a five-hour session limit and a weekly limit. Max plans also have a separate weekly limit for Fable. These limits are shared across Claude and Claude Code, meaning all activity in both tools counts against the same limits." — https://support.claude.com/en/articles/11145838

Max plans also have a weekly usage limit that applies across all models." "we may limit your usage in other ways, such as weekly and monthly caps or model and feature usage, at our discretion." — https://support.claude.com/en/articles/11049741
- `claude -p` / Agent SDK on subscription login: "still draw from your subscription limits" (help center 15036540). Cloud sessions: "share rate limits with all other Claude and Claude Code usage within your account."
- Connectors: no separate pool stated; "Tools and connectors are token-intensive" (limits article).
- No absolute numbers are published. Prices: Pro $20/mo ($17/mo annual); Max 5x $100; Max 20x $200 (claude.com/pricing; Max article). Opus available on Pro and Max; Fable on Max ("50% of weekly limits"), Pro via usage credits only (pricing table).

### A4. Monthly API credits with Max (new Oct 7, 2026)
From https://support.claude.com/en/articles/17154008 (paraphrase of fetched content, key quotes verbatim):
- Amounts: Max 5x **$100/month**, Max 20x **$200/month**; Team $20/$100 per seat, pooled, "capped at $500".
- "Free, Pro, and Enterprise plans aren't eligible." Pro: "No. The credits are available on Max and Team plans only."
- Eligibility: active, good standing; "New subscribers can claim once they've been on an eligible plan for seven days."
- Claim: "To claim your credit, you link a Claude Console organization to your plan." (Settings > Billing; Console role Owner/Admin/Billing.)
- Covers: "any available Claude model on the Claude Platform" — Messages API, Message Batches, Console Playground, Managed Agents, Agent SDK / `claude -p` **when run with an API key** from the linked org.
- Excludes: interactive Claude Code (terminal/IDE/desktop/web), extra usage in Claude apps, Bedrock/Vertex/Foundry. Pro/Max article: "Monthly API credits included with Max plans can't be used in Claude Code or the Claude apps, including for usage credits."
- "Unused credits expire at the end of each billing cycle." No rollover.
- Beyond credits: if the org has no other credits, "API requests stop until the next monthly grant." "Usage is never charged to your Claude plan." If you bought credits or enabled auto-reload, those are used.
- Not the same as the June "Agent SDK credit": "That credit isn't available."
- Relevance: on Max, a **real API key** with a hard $100/$200 monthly ceiling and no automatic overage (if no purchased credits/auto-reload). This removes the ToS gray zone for backend calls, within that budget. At list prices (Opus 5.5 $4 in / $20 out per MTok; Sonnet 5.5 $2/$10; Haiku 5.5 $0.10/$0.50 ≤100K) — claude.com/pricing.

### B6. Local models (Ollama / LM Studio on Apple Silicon)
- Cost: free; data stays local.
- Context: Ollama defaults "< 24 GiB VRAM: 4k context; 24-48 GiB VRAM: 32k context; >= 48 GiB VRAM: 256k context" and "Tasks which require large context like web search, agents, and coding tools should be set to at least 64000 tokens."
