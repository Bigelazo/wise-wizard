Ticket: [#3](https://github.com/Bigelazo/wise-wizard/issues/3). Fecha de la investigación: 2026-10-29/30. Las fuentes son páginas de los proveedores consultadas en esas fechas. Las citas son textuales y van en su idioma original, salvo las marcadas como "(paráfrasis)". Cuando una página no se pudo consultar directamente (el help center de OpenAI y openai.com responden 403 a las consultas automatizadas), se indica y la afirmación queda marcada como de menor confianza.

## A. Suscripción de Claude (Pro / Max)

### A1. ¿Puede la app propia del suscriptor llamar a `claude -p` o al Agent SDK con su login de claude.ai?

#### Qué dicen los documentos que rigen

**1. Los Consumer Terms (vigentes desde el 8 de octubre de 2025) rigen Pro y Max, incluido Claude Code.**
- Página legal de Claude Code: "Consumer Terms of Service - for Free, Pro, and Max users" — https://code.claude.com/docs/en/legal-and-compliance
- La §3 de los Consumer Terms prohíbe: "Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it, to access the Services through automated or non-human means, whether through a bot, script, or otherwise." — https://www.anthropic.com/legal/consumer-terms
- §2: "You may not share your Account login information, Anthropic API key, or Account credentials with anyone else. You also may not make your Account available to anyone else."
- Nota: según "these Terms", las API keys se rigen por los Commercial Terms; "this does not include Claude.ai or Claude Pro use for individuals".

Es decir, el acceso automatizado con una suscripción está prohibido **salvo que Anthropic "explicitly permit[s] it"**. La pregunta es si la documentación de Claude Code cuenta como ese permiso explícito para usar `claude -p` o el SDK.

**2. La propia documentación de Anthropic describe el uso headless autenticado con la suscripción.**
- Documentación de autenticación, `claude setup-token`: "For CI pipelines, scripts, or other environments where interactive browser login isn't available, generate a one-year OAuth token with `claude setup-token`" … "This token authenticates with your Claude subscription and requires a Pro, Max, Team, or Enterprise plan. It can only make model requests, so it can't establish Remote Control sessions or fetch claude.ai connectors. MCP servers you configure locally still work." — https://code.claude.com/docs/en/authentication
- Ítem 5 de la lista de precedencia: "`CLAUDE_CODE_OAUTH_TOKEN` environment variable. A long-lived OAuth token generated by `claude setup-token`. Use this for CI pipelines and scripts where browser login isn't available."
- Documentación headless: "`--bare` is the recommended mode for scripted and SDK calls", pero "bare mode doesn't use your subscription login" / "In bare mode, Claude Code never reads OAuth credentials or the system keychain." (`claude -p` sin `--bare` sí usa el login de la suscripción.) — https://code.claude.com/docs/en/headless
- Help center, "Use the Claude Agent SDK with your Claude plan" (textual, consultado en bruto):
  - "Update October 7, 2026: Claude Max and Team plans now include monthly API credits. They cover the Claude API, Claude Managed Agents, and the Claude Agent SDK and claude -p when you run them with an API key from your linked Claude Console organization. Nothing changes for your plan: when you're signed in with your Claude plan, the Claude Agent SDK and claude -p still draw from your subscription limits."
  - "Update June 15, 2026: We've paused the previously-announced changes to Claude Agent SDK usage. For now, nothing has changed: Claude Agent SDK, claude -p, and third-party app usage still draw from your subscription limits."
  - https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan
- Página legal: "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK."

**3. Las restricciones apuntan a desarrolladores que ofrecen el login de claude.ai a *terceros*.**
- Página legal, "Authentication and credential use":
  - "**OAuth authentication** is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications."
  - "**Developers** building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider. Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow."
  - "… Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code …"
  - "Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice."
- Resumen del Agent SDK: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Use the API key authentication methods described in the Quickstart instead." — https://code.claude.com/docs/en/agent-sdk/overview
- El mismo resumen dice además: "Use of the Claude Agent SDK is governed by Anthropic's Commercial Terms of Service, including when you use it to power products and services…". Esto convive mal con la vía del login de suscripción, que se rige por los Consumer Terms, y queda marcado como ambigüedad.
- Help center, "Log in to your Claude account":
  - "Subscription plans can only be used by subscribers, and the usage included in these plans is designed to support ordinary use of native Anthropic applications, including the Claude web, desktop, and mobile applications and Claude Code."
  - "The preferred way to access Anthropic services using third-party software, tools, or services ("third-party tools"), including open-source projects, is through API key authentication … Anthropic may at its discretion allow paid subscribers who have enabled usage credits to use certain third-party tools … but reserves the right to draw use of such third-party tools from usage credits rather than subscription limits. … Use of third-party tools that misrepresent their identity to Anthropic's servers, attempt to route third-party traffic against subscription limits, or otherwise violate applicable terms or policies is prohibited and such use may be enforced against."
  - "If you're building a product, application, or tool for others, use API key authentication…"
  - https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account
- Historia (fuentes secundarias, solo como contexto): en febrero de 2026, una versión de la página legal habría dicho que usar tokens OAuth de suscripción "in any other product, tool, or service — including the Agent SDK — is not permitted", y un post de DevRel de Anthropic lo llamó "doc cleanup". Ese texto **no** está en la página actual. El 4 de abril de 2026, Anthropic sacó los harnesses de terceros (empezando por OpenClaw) de los límites de la suscripción y los pasó a extra usage pagado (InfoWorld, The Register, etc.). En mayo de 2026 anunció que el uso del Agent SDK y de `claude -p` pasaría a un crédito separado desde el 15 de junio; ese cambio quedó en pausa (aviso oficial más arriba).

#### Uso personal de un solo usuario

Ninguna página de Anthropic trata directamente el caso de "la app privada de un solo usuario del propio suscriptor, que lanza `claude -p` en cada petición". Los documentos hablan de (i) "ordinary, individual usage of Claude Code and the Agent SDK", (ii) desarrolladores externos que ofrecen el login a *sus usuarios* y (iii) "third-party tools".

#### Clasificación

| Escenario | Estado | Base |
|---|---|---|
| (a) El suscriptor maneja Claude Code de forma interactiva (terminal, IDE, escritorio, Remote Control desde el celular), incluidos servidores MCP propios | **Claramente permitido** | Artículo de Pro/Max del help center; docs de MCP; docs de Remote Control |
| El suscriptor ejecuta `claude -p` o el Agent SDK él mismo, con su login, para sus propios scripts | **Permitido según la documentación actual** (el help center dice que "draw[s] from your subscription limits"; `setup-token` está documentado "for CI pipelines and scripts") | Help center 15036540; docs de autenticación |
| (b) Un proceso backend del propio suscriptor lanza `claude -p` (binario sin modificar, con su login o `setup-token`) en cada petición de una app de un solo usuario que solo él usa | **Zona gris.** No se trata expresamente. A favor: la documentación respalda explícitamente los scripts y el SDK con la suscripción; el uso sigue siendo "individual"; no hay usuarios terceros; el binario sin modificar inicia sesión por el flujo propio de Anthropic. En contra: los Consumer Terms prohíben el acceso automatizado o no humano salvo que esté "explicitly permit[ted]"; el help center dice que las suscripciones son para "ordinary use of native Anthropic applications"; Wise Wizard es una "third-party tool" en el sentido del help center; los límites suponen "ordinary, individual usage"; Anthropic "may at its discretion" pasar ese uso a usage credits pagados y hacer cumplir las reglas "without prior notice". | Lo anterior |
| Igual, pero la app está expuesta a internet y solo el suscriptor inicia sesión | La misma zona gris; el riesgo aumenta si alguien más puede usarla ("You also may not make your Account available to anyone else") | Consumer Terms §2 |
| Ofrecer "Sign in with Claude" o el login de claude.ai en la app; recolectar o guardar tokens de claude.ai; atender a otros usuarios con el propio plan | **Claramente prohibido** | Página legal; resumen del Agent SDK; help center |
| Modificar o suplantar el cliente, o extraer el token OAuth para llamar a la API directamente desde código propio (sin pasar por el binario de Claude Code) | **Claramente prohibido** ("misrepresent their identity"; "collect, store, or intermediate … session tokens") | Help center; página legal |
| Usar `--bare` con la suscripción | Técnicamente imposible (el modo bare ignora OAuth) | Docs headless |

Notas prácticas (hechos): los tokens de `setup-token` duran un año y "can only make model requests" (sin conectores de claude.ai ni Remote Control). Las credenciales normales de `/login` vencen y hay que renovarlas: "A background session … or a Remote Control session that outlives the login stops making progress once the credential expires."

Es una superficie interactiva y propia de Anthropic, sin el problema del acceso automatizado.

### A3. Forma de los límites de uso

- "Both Pro and Max plans have a five-hour session limit and a weekly limit. Max plans also have a separate weekly limit for Fable. These limits are shared across Claude and Claude Code, meaning all activity in both tools counts against the same limits." — https://support.claude.com/en/articles/11145838
- "Note that your usage of all different Claude product surfaces (claude.ai, Claude Code, Claude Desktop) counts towards the same usage limit." — https://support.claude.com/en/articles/11647753
- Max: "Max 5x includes five times the Pro plan's per-session usage allowance" / "Max 20x includes 20 times…". "Your session-based usage limit will reset every five hours. Max plans also have a weekly usage limit that applies across all models." "we may limit your usage in other ways, such as weekly and monthly caps or model and feature usage, at our discretion." — https://support.claude.com/en/articles/11049741
- `claude -p` y el Agent SDK con el login de la suscripción: "still draw from your subscription limits" (help center 15036540). Sesiones en la nube: "share rate limits with all other Claude and Claude Code usage within your account."
- Conectores: no se indica un cupo separado; "Tools and connectors are token-intensive" (artículo de límites).
- No se publican cifras absolutas. Precios: Pro $20/mes ($17/mes en plan anual); Max 5x $100; Max 20x $200 (claude.com/pricing; artículo de Max). Opus está disponible en Pro y Max; Fable, en Max ("50% of weekly limits") y en Pro solo con usage credits (tabla de precios).
- Contexto: "On paid plans, the newest models support up to a 1M token context window, while others support 500K or 200K tokens." (artículo de límites)
- Entrenamiento, según los Consumer Terms: "We may use Materials … including training our models, unless you opt out of training through your account settings."
- Al superar el límite: "usage credits" opcionales y pagados. Para evitar cobros, hay que rechazar la opción de crédito de API y no definir `ANTHROPIC_API_KEY` ("Claude Code will use this API key … resulting in API usage charges").

### A4. Créditos mensuales de API con Max (nuevo desde el 7 de octubre de 2026)

Desde https://support.claude.com/en/articles/17154008 (paráfrasis del contenido consultado, con las citas clave textuales):
- Montos: Max 5x **$100/mes** y Max 20x **$200/mes**; Team, $20/$100 por puesto, en un fondo común "capped at $500".
- "Free, Pro, and Enterprise plans aren't eligible." Sobre Pro: "No. The credits are available on Max and Team plans only."
- Elegibilidad: cuenta activa y al día; "New subscribers can claim once they've been on an eligible plan for seven days."
- Cómo se reclaman: "To claim your credit, you link a Claude Console organization to your plan." (Settings > Billing; en Console se necesita rol Owner, Admin o Billing).
- Cubren "any available Claude model on the Claude Platform": Messages API, Message Batches, Console Playground, Managed Agents, y el Agent SDK o `claude -p` **cuando se ejecutan con una API key** de la organización vinculada.
- No cubren: Claude Code interactivo (terminal, IDE, escritorio, web), el extra usage de las apps de Claude, ni Bedrock, Vertex o Foundry. Artículo de Pro/Max: "Monthly API credits included with Max plans can't be used in Claude Code or the Claude apps, including for usage credits."
- "Unused credits expire at the end of each billing cycle." No se acumulan de un mes a otro.
- Al agotarlos: si la organización no tiene otros créditos, "API requests stop until the next monthly grant." "Usage is never charged to your Claude plan." Si se compraron créditos o se activó la recarga automática, se usan esos.
- No es lo mismo que el "Agent SDK credit" anunciado en junio: "That credit isn't available."
- Relevancia: en Max hay una **API key real** con un techo mensual fijo de $100/$200 y sin cobro automático por exceso (si no hay créditos comprados ni recarga automática). Eso elimina la zona gris de los términos para las llamadas desde el backend, dentro de ese presupuesto. Precios de lista: Opus 5.5 a $4 de entrada y $20 de salida por MTok; Sonnet 5.5 a $2/$10; Haiku 5.5 a $0.10/$0.50 (≤100K) — claude.com/pricing.

## B. Otros proveedores

### B1. OpenAI

**El plan de ChatGPT no incluye uso de la API clásica.** Fragmentos de búsqueda del help center (openai.com y help.openai.com bloquean la consulta automatizada; menor confianza): Plus se cobra aparte de la API, y "ChatGPT and the API platform" tienen facturación separada. Existe un artículo "API credits benefit for eligible ChatGPT subscriptions" (https://help.openai.com/en/articles/20001626), pero no se pudo consultar: **sin verificar**, hay que revisarlo a mano.

**Codex CLI y SDK con el login de ChatGPT.**
- "Codex supports two ways … Sign in with ChatGPT for subscription access; Sign in with an API key for usage-based access." — https://developers.openai.com/codex/auth
- "Use API key authentication for programmatic Codex CLI workflows, such as CI/CD jobs. Don't expose Codex execution in untrusted or public environments."
- `codex exec` "reuses saved CLI authentication by default." La autenticación gestionada por ChatGPT en CI aparece documentada como avanzada: "for … users who need ChatGPT/Codex rate limits instead of API key usage." "Do not use this workflow for public or open-source repositories." — https://developers.openai.com/codex/noninteractive ; https://learn.chatgpt.com/docs/auth/ci-cd-auth ("advanced workflow for enterprise and other trusted private automation").
- Modo headless: `codex exec --json` (eventos JSONL), `--output-schema`, `-o`. Login headless: `codex login --device-auth` o copiar `~/.codex/auth.json` (la documentación muestra `docker cp`).
- Codex SDK (`@openai/codex-sdk`, `openai-codex` en Python): "Integrate Codex within your own application"; "Use the library server-side". — https://developers.openai.com/codex/sdk
- Planes (precios de Codex): Free $0, Go $8, Plus $20, Pro desde $100 ($100/$200/$500). Estimación de mensajes locales en Plus cada 5 h: GPT-6.1 Sol 15–160, GPT-6.1 Terra 35–285, GPT-6 Luna 350–3,000. "Pro plans currently have no five-hour limit." "Weekly limits may also apply." — https://developers.openai.com/codex/pricing
- Modelos: las páginas de API de GPT-6.1 Sol y Terra indican "1,050,000 context window", con entrada de texto e imagen.

**Nuevo y directamente relevante: uso del plan con "Sign in with ChatGPT" en apps open source o alojadas localmente** (documentación oficial para desarrolladores):
- "For open-source developers: Let users run AI workloads in your tools with their ChatGPT plan, without requiring them to provide an API key." "ChatGPT plan usage is available to all open-source partners and selected private clients." — https://developers.openai.com/siwc/quickstart
- "These docs explain ChatGPT plan usage for open-source and locally hosted apps. If you're interested in offering it in a paid or remotely hosted app, complete the interest form." — https://developers.openai.com/siwc/token-sharing-open-source
- Mecanismo: OAuth (registro dinámico de clientes, PKCE, loopback en 127.0.0.1) y luego `POST https://api.openai.com/v1/responses` con el access token de OAuth como Bearer; `store: false`, `stream: true`. Una guía "Self-hosted VMs" cubre ejecutar "an open-source app on a remote virtual machine": el OAuth se completa en local y las credenciales se transfieren por SSH. — /siwc/token-sharing-open-source/models-and-inference, /self-hosted-vms
- Limitaciones (preview): no se admiten campos como `temperature`, `max_output_tokens` ni `previous_response_id`; herramientas no admitidas: "Image generation, file search, Code Interpreter, native computer use, hosted MCP/connectors"; "Web search remains subject to model and account/workspace policy." "Text, images, and files are supported when the selected model accepts them." — /preview-limitations
- Uso: "It uses your Codex / ChatGPT work usage included in your plan." "App usage counts toward your existing plan limits." El usuario puede limitar cada app a un porcentaje del uso semanal. Planes elegibles: "ChatGPT Plus and Pro" (un fragmento del help center agrega Go: hay discrepancia). — https://learn.chatgpt.com/docs/sign-in-with-chatgpt
- Puntos grises: si una app personal privada, self-hosted y *no publicada como open source* cuenta como "open-source and locally hosted"; un self-hosting expuesto a internet podría contar como "remotely hosted". Los Terms of Use de OpenAI no se pudieron consultar (403): hay que revisar a mano la cláusula "automatically or programmatically extract data or Output".
- Datos: aplican los controles de datos de ChatGPT para consumidores (no verificado en esta sesión).

### B6. Modelos locales (Ollama / LM Studio en Apple Silicon)

- Costo: gratis; los datos se quedan en local.
- Contexto: Ollama usa por defecto "< 24 GiB VRAM: 4k context; 24-48 GiB VRAM: 32k context; >= 48 GiB VRAM: 256k context", y "Tasks which require large context like web search, agents, and coding tools should be set to at least 64000 tokens." "Setting a larger context length will increase the amount of memory required." — https://github.com/ollama/ollama/blob/main/docs/context-length.mdx
- Qué es realista para este caso (evaluación propia, no afirmación del proveedor): en un Mac de 16–36 GB son prácticos modelos de ~8–30B con 32k–64k de contexto; un contexto de ~300k tokens no es práctico en local (memoria del KV-cache y tiempo de prefill). Conviene RAG (embeddings y los k fragmentos de página más relevantes) en vez de contexto largo. Para responder con respaldo en las Fuentes, generar Cartas y evaluar respuestas, la calidad de los modelos abiertos medianos es usable, pero queda por debajo de los modelos frontera al evaluar con matices y al respetar un formato estricto de citas. No traen búsqueda web; Scholar habría que implementarlo por cuenta propia, sujeto a su política de robots.
